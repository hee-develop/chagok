# 채비 넣기

폰 앱에서 일정마다 채비(챙길 것)를 한 줄로 적으면, 차가 탈 때 읽어 줍니다. PT 모바일 장면의 'KIA 직관에 채비 유니폼·응원봉·티켓 넣기'입니다.
앱에서 적은 채비는 차곡 서버에만 두고 캘린더는 건드리지 않습니다. 차는 앱 채비를 먼저, 없으면 일정 메모를 읽습니다.

## 폰

- 3단계(장소 빈 일정 채우기) 카드 아래에 채비 줄이 있습니다. 적어 둔 채비가 있으면 '채비 · 유니폼·응원봉·티켓'과 [채비 수정], 없으면 [채비 넣기]입니다. 이동 없음 일정은 차로 가지 않으므로 채비 줄을 두지 않습니다.
- [채비 넣기]·[채비 수정]은 `setup/schedule-care` 화면(`phone/src/features/fill-places/ScheduleCareScreen.tsx`)으로 갑니다. 한 줄 입력(100자), [저장], 적어 둔 채비가 있으면 [채비 지우기], [취소]가 있습니다. 바꾼 것이 없으면 저장할 수 없습니다.
- 저장하면 일정 목록으로 돌아가고 목록은 서버에서 다시 읽습니다. 실패하면 화면에 머물고 [다시 시도], 4xx(일정이 사라짐)면 '일정이 바뀌었어요' 안내와 [일정 목록으로]입니다. 요청은 기존 10초 제한(`requestWithTimeout`)을 씁니다.
- '오늘 탭'(첫 설정 뒤 홈)은 아직 없습니다. 화면 시안을 확인하면 같은 채비 화면을 오늘 탭에서도 엽니다.

## 서버 API

- `PUT /schedules/:id/care`: `{ care: string | null }`. 앞뒤 공백을 지우고 줄바꿈·연속 공백은 공백 하나로 줄입니다. 빈 글이나 `null`은 지웁니다. 100자(`MAX_CARE_LENGTH`) 초과, 다른 키, 문자열이 아닌 값은 400이고 저장하지 않습니다. 선택한 캘린더에 없는 일정은 404입니다. 종일 일정에도 둘 수 있습니다(하루 전체 채비). 응답은 `{ id, care }`입니다.
- `GET /schedules/today`·`GET /schedules/places`의 일정마다 `care: string | null`이 있습니다.
- 저장은 장소 보정과 같이 메모리(목 사용자 한 명)이고 서버를 다시 켜면 사라집니다. 폰 일정이 바뀌어 사라진 일정의 채비는 버립니다.

## 차가 읽는 규칙 (`MemoNote.forBoarding`)

| 탑승 | 읽는 것 |
| --- | --- |
| 그날 첫 탑승 | 대상 일정과 오늘의 다른 일정(종일 포함, 도착·건너뜀 제외)의 앱 채비를 모읍니다. 대상 일정이 먼저입니다. 하나도 없으면 지금처럼 대상 일정의 메모를 읽습니다. 다른 일정의 메모는 채비인지 알 수 없어 읽지 않습니다. |
| 재탑승 | 대상 일정의 앱 채비만 읽습니다(재탑승 카드는 아직 없음). |

- 당일치기에서는 첫 탑승이 집을 나서며 챙길 마지막 기회라서, 대상 일정이 아닌 일정(예: 08:50 탑승의 대상은 13:00 육전집 점심인데 채비는 17:00 KIA 직관)의 채비도 첫 탑승에 읽습니다. 2026-11-13 사용자와 정했고, 회의에서 바뀌면 `MemoNote.forBoarding` 한 곳만 고칩니다.
- 문장(`Phrases.careSentence`): 한 일정이면 "KIA 직관 채비는 ‘유니폼·응원봉·티켓’이에요. 출발할까요?", 여러 일정이면 "오늘 채비는 ‘…’이에요. 출발할까요?". 읽을 글이 30자(`Rules.MEMO_READ_MAX_CHARS`)를 넘으면 "KIA 직관 채비가 있어요."·"오늘 챙길 채비가 있어요."만 말합니다. 질문은 출발 하나뿐입니다.
- 채비 타일에는 항목을 '·'·','·'/'로 나눈 태그를 두고, 같은 항목은 한 번만 둡니다.

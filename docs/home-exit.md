# 위치 어댑터와 집 하차

정책서 3장 '도착'·'집', 4·6장 '하차', 9장 '채비 하차 때·채비가 없으면', 12장 '도착 반경 300m'·'집 반경 300m(가안)'. 차 위치를 읽어 **일정 장소 도착을 위치로 판단**하고, 집에 내릴 때 **집 하차 카드**를 한 번 보입니다.
카드의 모양·5초 닫힘·[챙겼어요]·다른 카드와의 관계는 일정 장소 하차 카드([`docs/exit-card.md`](exit-card.md))를 그대로 따릅니다. 아래는 위치와 집에 관한 것만 적습니다.

## 위치 어댑터 (`runtime/LocationAdapter`)

- 표준 `LocationManager`로 읽고 `Event.LocationChanged(position, ageMillis)`로 세션에 넣습니다. 실차의 Pleos FusedLocation(`pleos.car.permission.FUSED_LOCATION`, SDK 신청 '준비 중')으로 바꿀 때는 `Locator` 인터페이스(`runtime/Ports.kt`)만 새로 구현해 `Adapters.location`에 끼웁니다.
- **포그라운드 위치 권한만** 씁니다(`ACCESS_FINE_LOCATION`·`ACCESS_COARSE_LOCATION`, 백그라운드 위치 권한 없음). 그래서 **차곡 화면이 보이지 않으면 위치를 못 받는 것이 예상 결과**이고, 그동안의 위치 판정은 건너뛰어집니다.
- 갱신(Pleos 리소스 가이드: 불필요한 센서 수집 최소화):
  - 주기 갱신은 **앱이 앞에 있을 때만** 30초·50m(제공자는 GPS → fused → network 순).
  - 수동(passive) 갱신은 10초·25m: 센서를 켜지 않고 다른 앱(내비)이 얻은 위치만 받습니다.
  - **P단에 넣는 순간** `SessionHost.post`가 `refreshNow`(시스템의 마지막 위치)를 gear 이벤트보다 먼저 세션에 넣습니다.
  - Suspend(시동 끔)에서 멈추고 돌아오면 **권한을 다시 확인해** 켭니다.
- 측위 시각은 시각이 아니라 **나이**(`ageMillis`, `elapsedRealtimeNanos`로 잼)로 보냅니다. 세션이 자기 시계(데모 시계)의 지금에서 나이를 빼 측위 시각으로 삼으므로 두 시계를 섞어 비교하지 않습니다. 내비 답(`Effect.RequestLocation`의 답)과 debug 주입은 방금 측위한 값이라 나이 0입니다.
- **기어·시동은 위치 권한과 무관하게 늘 켭니다**(`PermissionGate.ALWAYS_ON`, `SessionHost.start()`). 위치만 권한 결정 뒤에 켭니다(`AFTER_PERMISSION`, `startPermissionGatedSources`).
- 권한은 기존 권한 설명 카드 흐름에 합류합니다("현재 위치를 쓸게요." → [계속할게요]). 주행 중에는 미루고, **세션 카드(탑승·연결·하차 등)가 떠 있으면 미뤘다가 닫힌 뒤** 보입니다(`MainActivity.render`). 거부하거나 대략 위치(COARSE)만 허용하면 "위치 권한이 없어 위치로 도착을 알 수 없어요…" 한 줄만 보이고 **위치 판정만 빠집니다**(기어·시동·내비 도착은 그대로).

## 내비 위치 질의(`Effect.RequestLocation`)와의 관계

둘 다 같은 `Event.LocationChanged`로 들어오고 **측위 시각 규칙이 같습니다**(이번 주행 시작 뒤 측위·5분 이내).

1. 달린 뒤 P단에 넣을 때 어댑터가 읽어 둔 위치(`freshLocation`)로 먼저 판정합니다.
2. 그 위치가 없거나 낡았거나, 일정 장소·집 어디와도 멀면 **내비에 현재 위치를 한 번 묻고**, 답(나이 0)이 오면 아직 P단일 때 같은 규칙으로 다시 판정합니다. 물을 후보(시간 창 안의 일정 장소나 등록한 집)가 하나도 없으면 묻지 않습니다.
3. 내비가 답하지 않으면 어댑터 위치로 한 판정이 그대로 남습니다. 기다리는 동안 낡은(5분 초과·이번 주행 전) 위치가 먼저 와도 쓰지 않고 판정에 쓸 수 있는 위치가 올 때까지 같은 P단에서 기다립니다.

## 위치로 하는 일정 장소 도착 (`DriveSession.judgeByLocation`)

사용자 결정(heka `chagok-location-arrival-rules-2026-11-11`)에 따라 **정책서 12장에 가안으로 추가할 값**을 둡니다. 판정은 **내비 도착 대기가 없을 때, 실제로 달린 뒤 넣은 P단에서만** 합니다(앱 시작 P단·달리지 않고 넣은 P단은 하차가 아님).

- 쓰는 위치: **이번 주행(D·R) 시작 뒤에 측위했고 측위한 지 `Rules.LOCATION_MAX_AGE`(5분, 가안) 이내**인 것만. 이번 주행 시작은 마지막 P단 뒤 처음 D·R이 된 시각(`driveStartedAt`)이고, 주행을 시작하면 전에 받은 위치는 버립니다.
- 후보 일정: 오늘 일정 중 **도착·건너뜀이 아니고, 종일이 아니고, 장소를 알며, '시작 `Rules.ARRIVAL_WINDOW_LEAD`(60분, 가안) 전 ~ 종료' 창 안**인 것. 출발 제안이 목적지를 다시 묻는 여유(`ASK_DESTINATION_LEAD`)와 같은 값입니다. 창 밖 일정은 근처 P단이어도 도착이 아니고 집 판정으로 넘어갑니다.
- 후보 중 `Rules.ARRIVAL_RADIUS_METERS`(300m, 확정) 안인 것이 도착입니다. 여럿이면 **시작 시각이 지금과 가까운 것**(시작이 같은 거리면 먼저 시작하는 것).
- 도착이 기록되면 하차 카드는 일정 장소 하차의 기존 경로(`arrive` → `settleExitAtPark` → `showExitCard`)를 그대로 지납니다. 위치로 정한 하차 대기는 주행 제한 등으로 못 보였다면 **D·R이 되는 순간 지웁니다**(내비 도착 대기는 그대로 다음 P단을 기다림).

### main의 기존 동작에서 바뀐 점

| 전(main) | 지금 |
| --- | --- |
| 대상 일정(`target()`, 첫 번째 대기 일정) 하나만 300m로 판정 | 시간 창 안의 **모든 대기 일정** 중 300m 안 + 시작 시각이 가까운 하나 |
| 시간 조건 없음(하루 종일 근처 P단이면 도착) | 일정 '시작 60분 전 ~ 종료' 창 안에서만 |
| 주행 중 받은 위치는 나이·측위 시점 제한 없음(주행 시작 때 버리기만 함) | 이번 주행 시작 뒤에 측위했고 5분 이내만 |
| 내비 도착 대기가 있는 P단에서도 위치로 다음 일정 도착을 함께 기록 | 내비 도착 대기가 있는 P단은 **위치로 판정하지 않음**(내비 쪽이 먼저, 중복 없음) |
| 후보가 없어도(일정 장소 없음) 위치를 묻지 않음 | 같음. 단 등록한 집이 있으면 묻는다(집 판정 때문) |

## 집 하차 (`judgeByLocation` 2번)

위 일정 장소 도착이 없으면(창 밖 포함) 집을 봅니다.

- 집 좌표: **서버 자주 가는 곳의 집**을 `GET /schedules/today`의 `favorites`(`kind: "home"`)에서 받습니다. 차는 이 응답을 이미 받아 메모리에 두고 마지막 응답을 `ChagokStore`(`ScheduleCopyStore`)에 사본으로 저장하므로 서버를 못 받아도 지난번 집으로 판정합니다. 별도 요청은 없습니다. 앱 시작·일정 다시 받기 때 갱신됩니다(폰에서 집을 바꾸고 차에서 바로 반영되지는 않음 — 알려진 한계).
- 집 반경 `Rules.HOME_RADIUS_METERS`(300m, 가안) 안이고, **마지막 집 P단(또는 앱 시작) 뒤 집 반경 밖 위치를 한 번 이상 받았을 때만**(`leftHome`) 집 하차 카드를 보입니다. 집 P단이면 그 기록을 지웁니다(카드를 보이든 아니든). 집 밖 위치는 측위한 지 5분 이내여야 센다(시스템이 기억하던 어제 위치로 '떠났다'고 보지 않으려는 것).
- 카드(`Phrases.homeExitCard`): 상태 칩·5초·한 번 말하고 듣지 않음은 일정 장소 하차와 같습니다.
  - 챙길 **물건이 있으면** "콩물 챙기세요!" + 채비 타일 + 그 일정의 한 줄 + [챙겼어요].
  - **없으면** "오늘도 수고했어요."(alert 한 문장, 버튼 없음).
  - 한 줄: 물건 순서대로 처음 "한 줄이고 30자 이하"인 일정 것을 "‘제목’ 일정 메모: …"로 보입니다. 일정에 앱 채비(`Schedule.care`)가 있으면 메모보다 먼저 읽고 문구가 "채비"가 되는 우선순위도 일정 장소 하차와 같습니다(`MemoNote.forExit`). 말에는 섞지 않습니다.
  - 말(`Phrases.homeExitSpoken`)은 큰 문구이고 30자(`MEMO_READ_MAX_CHARS`)를 넘으면 "챙길 물건이 있어요."(물건은 화면에 남음).
- 물건(`HomePickup`): 제목에 **'픽업·찾기·사기·수령'이 낱말 끝**에 있는 일정의 제목에서 그 단어를 뺀 말('콩물 픽업' → '콩물'). '픽업하기'·'사기꾼'은 아님. 종일 일정은 뺍니다.
  - 센 일정: **도착으로 기록됐거나, 시작이 지났고 '장소가 있는데 건너뜀'이 아닌** 일정. 장소가 없는 일정은 건너뜀이어도 넣습니다(도착을 기록할 수 없어서).
  - 카드에는 같은 이름을 합치고 `Rules.HOME_ITEMS_MAX`(3개)까지만 올립니다. 알림 기록은 모든 일정을 셉니다.
- **같은 물건은 하루 한 번, 인사도 하루 한 번**: `Snapshot.homeItemsAnnounced`(알린 픽업 일정 ID)·`homeCardShown`에 저장하고(`SnapshotCodec`, 이전 저장분은 빈 기록), 날짜가 바뀌면·데모 초기화(`Reset`)에서 비웁니다. 남은 물건이 없는데 오늘 이미 인사했으면 카드가 없습니다.
- **내비 도착과 겹치면 내비 쪽이 먼저**입니다(내비 도착 대기가 있는 P단은 위치로 판정하지 않음). 한 P단에 카드는 하나입니다.
- 하차 카드 규칙은 그대로: 다른 카드(탑승 질문·출발 제안·연결 카드·일정 안내)가 떠 있거나 탑승 판단이 진행 중이거나 휴대폰 연결 전이면 띄우지 않고 대기를 버리며(알림 기록도 남기지 않음), 주행·주행 제한 중에는 띄우지 않고 대기를 둡니다(풀리면 띄움). 집 하차 대기는 **집 판정 뒤 15분**(`EXIT_PENDING_MAX`) 안에서만 살고 저장하지 않습니다. 시동 끔·연결 해제·초기화·D·R·진짜 탑승 판단 때 지웁니다.

## 연결 해제

연결이 풀리면(지금은 debug `paired=false`와 데모 초기화) `SessionHost.setPaired(false)`가 **받아 둔 일정·자주 가는 곳(집 좌표)과 저장된 사본을 지웁니다**(`ServerScheduleSource.clear`). 세션은 위치·집 밖 기록·하차 대기를 버립니다(`Event.Unpaired`). 진행 중이던 일정 받기는 건드리지 않아 끝나면 서버가 준 대로 다시 채워집니다. 서버의 연결 해제를 차가 알아채는 경로는 아직 없습니다(차는 한 번 연결되면 저장해 두고 다시 묻지 않음, `docs/pairing.md`). 그래서 서버·폰에서만 해제하면 차의 집은 지워지지 않습니다(폰·서버 작업 필요: 차가 앱 재진입 때 `GET /pairing/cars/:carId`로 해제를 알고 `Event.Unpaired`를 넣는 것).

## 시연용 입력 (debug 빌드)

- `chagok-debug://signal?loc=위도,경도`: 방금 측위한 위치(나이 0)를 넣고, **넣은 동안 위치 어댑터의 실제 위치(에뮬레이터 GPS)는 세션에 넣지 않습니다**. `loc=real`이면 주입을 풀어 실제 위치로 돌아갑니다. 기어보다 뒤에 처리하므로 `gear=P&loc=…`는 P단에서 내비에 물은 답이 됩니다. 어댑터 위치로 바로 판정하는 흐름은 `gear=D` → `loc=…` → `gear=P`를 따로 보냅니다.
- `chagok-debug://signal?advance=<분>`: 데모 시계를 앞으로 보냅니다(상태는 지우지 않음, 디버그 버튼 [시간 +10분]과 같음, 1~10080). 위치 나이는 데모 시계로 세므로 **`loc`은 `advance`를 보낸 뒤에** 넣습니다. 시간 창(60분 전)을 맞추는 데 씁니다.
- release 빌드에는 `loc` 주입·`advance`가 없고 위치 이벤트는 그대로 나갑니다(`DebugHooks.locationSink`).

## 알려진 한계

- 위치 판정은 P단에 넣는 순간(과 그때 내비에 물은 답)에만 합니다. P단에 선 뒤에 오는 주기 갱신으로 다시 판정하지 않습니다.
- 집 좌표는 일정 응답에 실려 와서 일정을 다시 받을 때만 바뀝니다. 서버가 집을 등록한 폰이 여러 대인 경우는 다루지 않습니다.
- 집 하차의 '집을 떠났다'는 프로세스가 다시 뜨면 잊습니다(저장하지 않음). 이동 중에 앱이 재시작하면 그 귀가는 하차 카드가 없습니다.
- `LOCATION_MAX_AGE` 5분, `ARRIVAL_WINDOW_LEAD` 60분, `HOME_RADIUS_METERS` 300m, 집 하차 대기 15분은 가안입니다(정책서 12장 표에 추가·확인 필요).

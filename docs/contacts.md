# 연락 상대 찾기(폰)

정책서 10.5: '늦을 때 연락'이 켜져 있고 연락처 권한이 있을 때, 폰이 일정을 읽으면서 **이동 일정마다** 연락할 상대를 미리 찾아 둡니다(작업 묶음 J8). 차는 이 이름으로 "{이름}에게 '{N}분 늦어요' 보낼까요?"를 묻고(9장), 문자는 폰이 보낼 때 연락처에서 번호를 다시 꺼내 만듭니다(J9).

## 프라이버시

- **서버에는 표시 이름만 보냅니다**(일정마다 0~2개). 전화번호·이메일·연락처 목록은 폰 밖으로 나가지 않습니다.
- **참석자 이름도 더는 보내지 않습니다**(정책 10.2: 이동 일정은 제목, 시작·종료, 장소 칸, 메모, 연락 상대 표시 이름만). 서버는 옛 폰 빌드가 `attendees`를 보내도 **무시**하고 저장하지 않습니다(11장 저장 항목에 없음).
- 로그에는 이름·번호·일정 내용을 남기지 않습니다(결과 이름과 단계만).
- 연락처는 앞에 있는 동안 5분(`CONTACT_CACHE_MS`) 메모리에 색인해 두고, 기능을 끄거나 권한을 잃으면 버립니다. 저장소(AsyncStorage)에는 두지 않습니다.

## 언제 찾는가

`features/calendar-sync/eventSync.ts`가 일정을 읽어 거른 뒤 보내기 직전에 `ContactFinder.prepare()`를 부릅니다(`features/contacts/contactFinder.ts`).

1. 서버 설정 `GET /settings`의 `lateContact`가 켜져 있어야 합니다. 읽지 못하면 마지막으로 안 값을 쓰고, 처음부터 못 읽었으면 찾지 않습니다(서버가 차에 '꺼짐'으로 알리는데 폰만 찾는 일이 없게).
2. 연락처 권한이 `granted`여야 합니다. 이 경로는 **권한 창을 띄우지 않습니다**(창은 설정 화면에서 '늦을 때 연락'을 켤 때만).
3. 둘 중 하나라도 아니면 모든 일정의 `contacts`는 빈 목록이고(이전에 찾아 보낸 이름은 다음 전송에서 지워짐) 연락처를 읽지도 않습니다.
4. **걸러진 일정**(온라인·건물 안, 서버로 보내지 않는 것)과 **종일 일정**(이동 일정이 아님)은 찾지 않습니다.

'늦을 때 연락'을 켜거나 끄고 권한 결정이 끝나면 일정을 다시 읽어 보냅니다(`onLateContactChanged`).

## 매칭 규칙 (`features/contacts/matchContacts.ts`, 순수 함수)

| 단서 | 규칙 |
| --- | --- |
| 참석자 이메일 | 연락처 이메일과 같으면 그 사람(대소문자·앞뒤 공백 무시) |
| 참석자 이름 | 연락처 이름과 **전체가** 같으면 그 사람(공백 여러 개·대소문자 무시). 일부만 같으면('박서연 팀장') 아님 |
| 제목·메모 속 이름 | 연락처의 **전체 이름**, 또는 **성을 뺀 두 글자 이상 이름**이 낱말로 들어 있으면 그 사람("민수랑 저녁" → 김민수) |
| 호칭("엄마", "김 과장님") | 연락처에 **그 이름으로 저장된 경우에만**(전체 이름 일치뿐, 성을 뺀 이름을 만들지 않음) |

- **성을 뺀 이름**(`givenNameOf`): 한글 3~4글자 이름만 대상이다. 3글자는 앞 한 글자가 성, 4글자는 복성(남궁·황보·제갈·사공·선우·독고·서문·동방·어금·망절)이면 두 글자, 아니면 한 글자다. 성을 떼고 **두 글자 미만**이면 쓰지 않는다('김수'). OS가 성·이름을 나눠 준 연락처는 그 이름 부분을 쓴다. 두 글자 이름('민수')·띄어쓰기가 있는 이름('김 과장님')·영문·호칭/관계 말('할머니' → '머니' 같은 오탐 방지, `KINSHIP`)은 전체 이름으로만 찾는다.
- **낱말 경계**(`wordIndexOf`): 이름 앞이 글자·숫자면 아니다('국민수영장'의 '민수'). 이름 뒤가 글자·숫자면 아니다. 단 뒤가 **조사·호칭**(랑·와·과·이·가·은·는·을·를·도·의·에게·한테·씨·님…, 이어서 붙어도 됨)으로 끝나는 한글이면 맞는다('민수랑', '김민수님'). '민수영장'은 아니다. 조사 목록은 가안이라 '민수이야기'처럼 '이'로 시작하는 낱말은 못 거른다.
- **결과**: 한 명이면 그 사람, 두 명이면 두 후보, **세 명 이상이면 못 찾은 것**(빈 목록, 12장 '연락 상대 후보 2명까지' 가안, `MAX_CONTACT_CANDIDATES`). 순서는 참석자 → 제목 → 메모, 같은 글에서는 먼저 나온 순이다.
- **같은 이름의 연락처**(동명이인·중복)는 한 사람으로 센다. 서버에는 표시 이름만 가서 차가 둘을 구별할 수 없기 때문이다. 보낼 때 `findNumberByDisplayName`이 번호가 서로 다르면 고르지 않고 null을 돌려주어 차가 번호를 묻는다.
- **번호가 하나도 없는 연락처**는 문자를 보낼 수 없어 찾지 않는다(정책서에 없는 가정).

## 번호 다시 꺼내기 (`findNumberByDisplayName`, J9가 쓴다)

`features/contacts/findNumber.ts`: 표시 이름(공백·대소문자 무시, 전체 일치)으로 연락처에서 번호를 꺼낸다. 한국 휴대폰 번호(`010########`, `+82 10…`도)를 먼저 고르고 없으면 첫 번호를 쓴다. 같은 이름이 여럿이어도 고른 번호가 모두 같으면 그 번호, 다르면 null. 권한이 없거나 못 읽으면 null이고 권한 창은 띄우지 않는다.

## 서버

- `PUT /events` 일정 항목에 `contacts: string[]`(선택): 앞뒤 공백을 뗀 비어 있지 않은 문자열 **2개 이하**, 각 100자 이하(`MAX_CONTACTS`, `MAX_CONTACT_NAME_LENGTH`). 없으면 빈 목록으로 본다. 어기면 400. `attendees` 필드는 와도 검증·저장하지 않는다.
- 저장은 일정과 함께 하루만 머문다(날짜가 지나면 삭제, 자리를 지우면 함께 삭제).
- `GET /schedules/today` 응답의 일정마다 `contacts: string[]`을 싣는다(기존 필드는 그대로, `attendees`는 옛 차 앱 호환으로 남기되 폰 일정은 늘 빈 목록). `GET /events` 응답은 `attendees` 대신 `contacts`를 준다.

## 목·테스트

- `EXPO_PUBLIC_CONTACTS_SOURCE=mock`이면 `fixtures/contacts/mock-contacts.json`(김민수·박서연·엄마·김 과장님·번호 없는 이영희). 폰 E2E가 이 값으로 돈다(권한 창 없음). 기본은 실제 `expo-contacts`(`expo-contacts/legacy`, Expo Go에서 동작하도록 캘린더와 같은 방식).
- 실제 연락처 권한 창과 실제 연락처 읽기는 Expo Go 에뮬레이터에서 자동으로 확인하지 않았다(수동 확인 항목).

# 가족에게 보내기

> **새 가족 모델과의 관계**: 이 문서는 PT용 '일정을 가족에게 보내기'(픽스처 가족, `POST /schedules/:id/family-request`, '전달됨' 고정)입니다. 새 모델(가족 초대·참여, 요청 4종, 보냄 → 전달 → 수락·거절 → 완료)은 [가족 묶기와 가족 요청](family-requests.md)이고, 이 경로는 그 모델의 **'약속 가기' 요청의 한 형태**(일정 하나를 가족에게 보내기)입니다. 폰 화면과 Maestro가 쓰고 있어 **응답 계약을 바꾸지 않고 그대로 두었고**(기본 자리·데모 경로), 새 모델의 받는 사람으로 픽스처 가족 id를 쓸 수는 없습니다. 폰 가족 탭(J10b)은 새 모델의 가족 묶기·요청 만들기·상태를 붙였지만 이 경로는 대체하지 않고 가족 탭 맨 아래 '일정으로 보내기' 입구로 그대로 둡니다(새 가족에게 일정을 보내려면 요청 만들기의 '약속 가기'를 씁니다). 이 입구는 미리 묶어 둔 가족에게만 보낼 수 있다고 화면에 안내합니다.

일정 하나를 주소·채비와 함께 미리 묶어 둔 가족에게 보냅니다. PT 모바일 장면의 "그 일정을 가족 한 명에게 보내고 '전달됨' 확인"입니다.
PT 범위(11/12)에 따라 보내기와 '전달됨' 상태까지 실제로 돌리고, 받는 쪽(가족의 차 브리핑·수락·완료)은 프로토타입·영상으로 보입니다.

## 가족

- 시연용 계정으로 미리 묶어 둔 가족은 `fixtures/family/members.json`이 단일 출처입니다(지금은 '엄마', '동생'). 가족 초대·묶기 화면은 없습니다.
- 서버 시작 코드(`server/src/index.ts`)가 다른 목 데이터처럼 읽어 `createApp({ familyMembers })`로 넘깁니다. 한 명 이상, id·이름이 빈 글이 아니고 id가 겹치면 시작할 때 멈춥니다.

## 서버 API

- `GET /family/members`: `{ members: [{ id, name }] }`
- `POST /schedules/:id/family-request`: `{ memberId }`. 보낼 때의 일정 내용(제목·시작·끝·보정한 주소(`locationText`·`place`)·채비(`care`))을 담아 저장하고 `status: 'delivered'`('전달됨')로 돌려줍니다.
  - 서버가 받아 가족 몫으로 저장하면 '전달됨'입니다(받는 쪽 앱이 없어 '읽음'·'수락' 단계는 아직 없음).
  - 같은 일정을 같은 가족에게 다시 보내면 요청을 하나로 두고 내용과 보낸 시각(`sentAt`)만 새로 합니다. 요청 id는 `<일정 id>:<가족 id>`입니다.
  - 오류: 다른 키·문자열이 아닌 `memberId`·묶어 두지 않은 가족은 400, 없거나 선택하지 않은 캘린더의 일정은 404, 종일 일정은 409입니다. 실패하면 저장하지 않습니다.
- `GET /family/requests[?scheduleId=]`: 보낸 요청을 최근에 보낸 것부터 줍니다.
- `GET /schedules/places`의 일정마다 `familyRequests: [{ memberId, name, status, sentAt }]`가 있습니다.
- 저장은 메모리(보낸 자리별, `docs/pairing.md`)이고 서버를 다시 켜면 사라집니다. 폰 일정이 바뀌어 일정이 사라져도 이미 보낸 요청은 남습니다.

## 폰

- 3단계 카드의 채비 줄 아래에 가족 줄이 있습니다. 보낸 가족이 있으면 '엄마에게 전달됨', 버튼은 [가족에게 보내기]입니다. 이동 없음 일정에는 없습니다.
- [가족에게 보내기] → `setup/family-send`(`phone/src/features/family/FamilySendScreen.tsx`): 묶어 둔 가족 목록, 가족마다 [보내기](보낸 뒤에는 '✓ 전달됨'과 [다시 보내기]), [완료].
  - 보내면 그 줄이 바로 '✓ 전달됨'으로 바뀌고 스크린리더에 '엄마에게 전달됐어요'를 알립니다. 목록으로 돌아가면 카드가 서버에서 새로 읽어 '엄마에게 전달됨'을 보입니다.
  - 불러오기·보내기 실패는 [다시 시도], 4xx(일정이 사라짐)는 '일정이 바뀌었어요' 안내와 [일정 목록으로]입니다. 요청은 기존 10초 제한(`requestWithTimeout`)을 씁니다.
- PT 문서의 '요청 보내기 시트'(오늘 탭) 시안은 아직 확인하지 못해 3단계 카드에서 여는 화면으로 만들었습니다.

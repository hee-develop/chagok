# 설정 화면 · 자리별 설정 · 첫 설정 '말 거는 방법'

정책서 10.8(설정)과 10.7(첫 설정 4단계 '말 거는 방법')입니다(작업 묶음 J5b). 폰이 스위치를 바꾸면 서버가 **운전자 자리별로** 저장하고, 차는 `/schedules/today` 응답의 `settings`로 받습니다. 차 쪽에서 이 값을 쓰는 일(플러스 모드 주행 중 말하기, 늦을 때 연락 묻기, 카드 없이 음성만)은 다음 묶음입니다.

## 서버

`server/src/routes/settings.ts`. 설정은 자리 데이터(`SeatData.settings`)에 들어 있다. `SEAT_DATA_POLICY`(자리 데이터 삭제·유지 선언)는 이 묶음의 기준 main에 없어서 선언을 더하지 못했다(병렬 묶음 J6이 추가한다). 들어오면 `settings`를 '끊으면 삭제 · 폰 바꾸기는 유지 · 연결 전 버킷에서 이어받음'으로 선언해야 한다.

```ts
type SeatSettings = { plusMode: boolean; lateContact: boolean; voiceOnly: boolean }; // 기본 모두 false
```

| API | 설명 |
| --- | --- |
| `GET /settings` | 그 자리의 설정(`SeatSettings`). 설정을 받은 적 없으면 모두 `false`. 읽기는 연결 전 버킷을 만들지 않는다 |
| `PUT /settings` | 본문에 보낸 키**만** 바꾼다(부분 갱신, 예: `{ "plusMode": true }`). 바뀐 전체를 돌려준다. 빈 객체·알 수 없는 키·boolean이 아닌 값·객체가 아닌 본문은 400, 64KB 초과는 413 |
| `GET /schedules/today` | 응답에 `settings: SeatSettings`를 더했다. **기존 필드는 그대로**다(`anchor`·`schedules`·`favorites`). 이 읽기는 옛 차 앱 호환 규칙을 그대로 따른다 |

### 어느 자리의 설정인가

새 API(`GET`·`PUT /settings`)는 `docs/place-resolve.md`의 장소 API와 같은 **엄격한 가드**(`placeRead`·`placeWrite`)를 쓴다. 옛 차 앱 호환 읽기를 적용하지 않는다.

| 식별 | 읽기 | 쓰기 |
| --- | --- | --- |
| 폰 토큰 | 그 자리 | 그 자리 |
| 모르는 폰 토큰 | 401 | 401 |
| 토큰 없음 + 기기 id | 그 기기의 연결 전 버킷(없으면 기본값, 만들지 않음) | 그 버킷(본문 검증 뒤 없으면 만듦, 주소별 속도 제한 429) |
| 차 토큰 | `driver=<seatId>` 필수(없으면 400 `driver-required`, 남의 자리는 403) | **403**(설정은 폰에서만 바꾼다) |
| 식별 없음 | 서버에 자리 있는 차가 **하나도 없을 때만** 기본 자리(데모·E2E 경로), 그 밖에는 빈 범위(기본값) | 같은 조건의 기본 자리, 그 밖에는 429 `unwritable` |

- **연결 전 버킷 이어받기**: 첫 설정 4단계(연결 전)의 값은 그 폰의 기기 id 버킷에 쌓이고, `POST /pair/claim` 때 그 기기의 버킷이 새 자리로 옮겨지면서 설정도 따라간다. 다른 기기의 버킷은 가져가지 않는다. 기기 id 없이 연결한 폰은 기본값으로 시작한다.
- **끊으면 삭제**: `DELETE /pair`(차 연결 끊기), `DELETE /car`(차곡 초기화)는 자리 데이터와 함께 설정을 지운다. 다시 연결하면 기본값으로 시작한다.
- **폰 바꾸기는 유지**: `mode: replace`는 일정·캘린더 선택·보정·채비만 새 폰 기준으로 바꾸고 설정은 건드리지 않는다. 새 폰의 연결 전 버킷에 설정이 있어도 **자리에 있던 설정이 이긴다**(가안).
- 연결 전 버킷을 밀어낼 때 기본값이 아닌 설정이 든 버킷은 '빈 버킷'이 아니라서 빈 버킷이 먼저 나간다.

## 폰

### 설정 탭 (`phone/src/features/settings/`)

위에서 아래로: 기본 말 걸기 카드 → **차곡이 말하는 방법**(스위치 셋, `SettingSwitches`) → **차**(연결 상태 + [차 연결 끊기]) → 캘린더(입구) → 장소(입구 셋) → 권한(캘린더·카메라·알림).

- **스위치 저장**(`useSettings`): 누르면 먼저 바뀌고(낙관적) 서버에 그 키만 `PUT`한다. 실패하면 직전 값으로 되돌리고 "저장하지 못했어요. 인터넷 연결을 확인하고 다시 시도해 주세요."를 그 줄 아래에 보인다. 저장은 **한 번에 하나**라 저장 중에는 스위치가 모두 비활성이다. 요청은 10초 제한(`requestWithTimeout`).
- **오래된 응답 막기**: 화면이 포커스를 얻을 때마다 다시 읽고(읽어 둔 값은 그동안 그대로 둠), 새 조회가 시작되면 이전 조회를 취소하며 응답을 반영하기 전에 그 조회가 현재 것인지 본다. 저장이 시작되면 진행 중인 조회를 취소하고, 저장 중이거나 저장이 끝난 뒤 도착하는 **저장 전에 시작한** 조회의 응답은 버린다(`epoch`). 탭을 오가도 진행 중인 저장은 끝까지 보낸다(언마운트 때만 취소).
- **늦을 때 연락**(정책 10.4 연락처): 켜는 저장이 성공하면 연락처 권한을 묻는다(처음 한 번만 시스템 창, `features/contacts/useContactsPermission`). 허용하면 안내가 없다. **거부하면 기능은 켜 둔 채** "상대를 미리 찾지 않아요. 차가 연락할 때 번호를 물어요."와 [연락처 설정 열기]가 그 줄 아래에 남는다(아직 안 물었으면 [연락처 켜기]). 저장이 실패하면 권한을 묻지 않는다. 문자 보내기 권한은 묻지 않고 "문자는 내용을 채운 문자 창으로 열어 드려요."만 항상 보인다.
- **차 연결 끊기**(`DisconnectSection`): 연결돼 있을 때만 보인다. [차 연결 끊기] → "차 연결을 끊을까요?" + 정책 10.9 안내("이 폰의 자리를 지워요. 서버에 있는 연결, 일정(장소·채비 포함), 기억한 장소, 자주 가는 곳, 이동 없음 목록, 도착 횟수, 보낸 가족 요청, 설정이 바로 삭제되고 차 화면 목록에서도 빠져요. 다시 쓰려면 차와 새로 연결해야 해요."). 문구는 서버가 자리 데이터 전체(`SeatData`)를 지우는 것과 맞춘 것이다(알림함·푸시 토큰도 함께 버려지지만 사용자에게 보이는 데이터가 아니라 문구에서 뺐다) → [끊기]. `pairingApi.disconnect`(`DELETE /pair`, 서버가 이미 모르는 401도 끊긴 것으로 보고 폰 토큰을 버림) 성공하면 연결 상태와 설정을 다시 읽어 연결 전 상태가 된다. 실패하면 안내와 [다시 시도]이고 연결은 그대로다. 끊는 동안 버튼을 막는다.
- **입구**: 자주 가는 곳·기억한 장소·이동 없음 목록은 모두 장소 탭(`router.navigate('/places')`)으로 이어진다.

### 첫 설정 4단계 '말 거는 방법' (`setup/talk`, `TalkScreen`)

정책 10.7: 캘린더 → 자주 가는 곳 → 장소 빈 일정 채우기 → **말 거는 방법** → 차 연결. 단계 표시는 **5단계**(`SETUP_TOTAL_STEPS = 5`)이고 차 연결이 5단계가 됐다(3단계 [다음]·[나중에 할게요] → `/setup/talk` → [다음]·[건너뛰기] → `/setup/pair-car`).

- 플러스 모드와 늦을 때 연락 스위치만 둔다(음성만은 설정 탭에서만). 같은 `SettingSwitches`라 저장·되돌리기·연락처 권한 분기가 설정 탭과 같다.
- 건너뛸 수 있다. [건너뛰기]는 아무것도 저장하지 않는다. 스위치는 누르는 즉시 저장되므로 켠 값은 [다음]이든 [건너뛰기]든 남는다.
- 연결 전이라 서버가 그 기기의 연결 전 버킷에 저장하고, 5단계에서 연결하면 자리로 이어진다. 4단계에 닿기만 한 것은 첫 설정을 끝낸 것으로 치지 않는다(끝 표시는 5단계의 [건너뛰기]·[완료]).
- 저장 중에는 [다음]·[건너뛰기]를 막는다. 설정을 읽지 못해도(오프라인) 안내와 [다시 시도]를 보이되 건너뛰어 이어 갈 수 있다.

## 가안·한계

- `voiceOnly`('화면 없이 음성만')는 정책서가 가안이라 설정 탭에만 있고, 첫 설정에는 넣지 않았다.
- 폰 바꾸기에서 새 폰의 버킷 설정보다 자리의 기존 설정을 우선한다(정책서에 없는 결정).
- 서버가 설정을 저장하므로(메모리) 서버를 다시 켜면 기본값(모두 꺼짐)으로 돌아간다. 폰은 설정 탭이 포커스를 얻을 때 다시 읽어 맞춘다.
- 연락처·문자 권한 사유 문구는 한국어만 있다(앱에 일본어 문자열이 아직 없다).
- 실제 연락처 권한 창은 Expo Go 에뮬레이터에서 자동으로 확인하지 않았다(E2E는 `EXPO_PUBLIC_CONTACTS_SOURCE=mock`이라 창 없이 허용으로 돈다). 수동 확인 항목이다.
- 설정은 폰이 쓰고 차는 읽기만 한다. 차 토큰으로 `PUT /settings`는 403이다.
- 데모 초기화 `DELETE /events`는 **기본 자리의 설정을 기본값으로** 되돌린다(실제 자리·연결 전 버킷은 그대로).
- 연락처 권한을 거부했으면 홈 맨 위에도 '켜면 이게 돼요'가 남는다('늦을 때 연락'이 켜져 있을 때만, 정책 10.4).
- 연락처는 읽기만 한다: `app.json`의 `android.blockedPermissions`로 `WRITE_CONTACTS`를 막아 쓰기 권한이 매니페스트에 들어가지 않게 했다(`expo-contacts` 플러그인이 읽기·쓰기를 함께 넣는다).

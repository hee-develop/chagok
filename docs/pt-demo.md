# PT 시연 진행표 (12/3)

PT 핵심 흐름을 에뮬레이터 두 대(차 `emulator-5554`, 폰 `emulator-5556`)와 노트북 서버로 보인다.
폰에서 일정 장소·채비를 넣고 → 차 화면 번호(QR)로 연결 → 08:50 첫 탑승 브리핑 → "응" → 길안내 → 도착 → 다시 타면 다음 일정.

## PT 일정 (`fixtures/schedules/pt-day.json`)

기준 시각을 **2026-12-03 08:50(서울)으로 고정**한 픽스처다. 폰(기준 시각을 보내지 않음)과 차(데모 시계)가 같은 시각을 본다(`anchor`, 서버 `server/src/fixture-types.ts`).

| 시각 | 일정 | 시연에서 |
| --- | --- | --- |
| 종일 | 광주 직관 | 브리핑 첫마디 "광주 직관 날이에요!" |
| 10:00 | 주간 회의(Zoom 주소) | 폰 3단계에서 '이동 없음 · 온라인 회의'로 흐리게. 차에는 안 감 |
| 13:00 | 육전집 점심 | **장소 비움** → 폰에서 '광주 육전집'을 넣는 장면. 첫 탑승의 대상 |
| 17:00 | KIA 직관 | 폰에서 채비 '유니폼 · 응원봉'을 적는 장면 |
| 21:00 | 콩물 픽업 | 오늘 일정 타일 셋째 줄 |

메모는 모두 비웠다(채비는 폰에서 라이브로 넣는다). 장소를 넣지 않고 차에 타면 "'육전집 점심' 어디로 가면 될까요?"라고 묻는다.

## 준비 (시연 30분 전)

1. 에뮬레이터 두 대를 켠다(차는 `-timezone Asia/Seoul`).
2. PT 일정으로 서버: `pnpm demo:pt server` (앞 창에 띄워 둔다. 평소 개발 서버가 8787에 떠 있으면 먼저 끈다)
3. 폰 Metro(목 캘린더):
   `cd phone && EXPO_PUBLIC_API_URL=http://127.0.0.1:8787 EXPO_PUBLIC_CALENDAR_SOURCE=mock CI=1 pnpm exec expo start --port 8081`
   - `adb -s emulator-5556 reverse tcp:8081 tcp:8081`, `adb -s emulator-5556 reverse tcp:8787 tcp:8787`
4. 차에는 기본 포트(8787) debug 앱: `cd car && ANDROID_SERIAL=emulator-5554 ./gradlew :app:installDebug`
5. 점검: `pnpm demo:pt check` → 모두 ✓이면 된다. 하나라도 ✗면 그 줄의 안내대로 고친다.

## 진행

| 장면 | 조작 | 보일 것 |
| --- | --- | --- |
| 1. 폰 첫 설정 | Expo Go로 `exp://127.0.0.1:8081` → 캘린더 → 자주 가는 곳 → 3단계 | 주간 회의가 흐리고 육전집 점심이 '장소 없음' |
| 2. 장소·채비 | 육전집 점심 [장소 넣기] → '육전집' 검색 → 광주 육전집. KIA 직관 [채비 넣기] → '유니폼 · 응원봉'. (선택) [가족에게 보내기] → 엄마 → '전달됨' | '일정 장소를 모두 확인했어요' |
| 3. 차 준비 | **이때** `pnpm demo:pt reset` (차 시계가 08:50에서 다시 간다) | 차에 연결 카드(QR · 번호) |
| 4. 연결 | 폰 [다음] → 4단계 '말 거는 방법'은 [건너뛰기] → 5단계에서 차 번호 입력(실기기면 [QR 찍기]) → [연결하기] | 폰 '✓ 차와 연결됐어요', 2초 안에 차가 브리핑 |
| 5. 탑승 브리핑 | (자동) | "광주 직관 날이에요! 1시 육전집 점심까지 4시간 10분이에요." + "KIA 직관 채비는 '유니폼 · 응원봉'이에요. 출발할까요?" |
| 6. 출발 | [응, 출발] (주입 모드는 길안내 요청 성공) | 길안내 시작 한 줄 |
| 7. 주행·도착 | 디버그 줄 [주행] → [도착] → [정차] | 주행 중에는 다음 일정 칩만, 도착 순간에는 말 없음 |
| 8. 다시 탐 | [시간 +10분] 두 번 → [탑승] | "5시 KIA 직관까지 …이에요." 한 줄 |

- 번호는 10분짜리이고 차가 만료 30초 전에 새 번호로 바꾼다. 폰에는 **차 화면에 지금 보이는 번호**를 넣는다.
- 3과 4 사이가 길어지면 브리핑의 남은 시간이 줄어든다(12분 지나면 "3시간 58분"). 장면 3은 연결 바로 전에 한다.
- 처음부터 다시: 서버를 껐다 켜고(`pnpm demo:pt server`, 장소·채비·연결이 메모리라 지워진다) 폰 Expo Go를 새로 연 뒤 1부터.
- 실제 내비·음성 인식으로 하려면 `PT_REAL=1 pnpm demo:pt reset`(회사 밖 네트워크에서만 확인됨, `docs/sdk-check.md`).

## 대비책

- **서버에 닿지 않을 때**: 차는 같은 날(12/3) 마지막으로 받은 일정 사본으로 브리핑한다. 리허설을 장면 5까지 끝까지 해 두면 장소·채비가 들어간 사본이 남는다.
  서버 없이 `pnpm demo:pt fallback`(연결은 유지)으로 08:50 탑승을 다시 띄우면 같은 브리핑에 "서버에 연결하지 못해 마지막으로 받은 일정 기준이에요."가 붙는다(2026-11-14 확인).
  폰 장면(1~4)은 서버가 있어야 하므로 녹화본으로 대신한다.
- **서버를 껐다 켜도(재시작) 차는 연결·사본·집을 유지한다**: 서버가 이 차를 모르면 `GET /pairing/cars/:carId`가 404이고 차는 이를 해제로 보지 않는다(타임아웃·5xx도 같다). 앱을 앞으로 가져와도 연결 카드로 돌아가지 않고 브리핑은 오늘 사본으로 한다. 단 서버 메모리가 비어 폰의 토큰은 401이 되므로 폰 장면은 처음부터 다시 한다.
- **`pnpm demo:pt reset`의 `paired=false`는 의도적 해제라 사본·집·탑승 기록을 지운다**(서버의 연결도 푼다). 연결을 유지한 채 서버만 다시 켠 경우와 다르다. 폰에서 연결을 해제해 서버가 '자리 0개'(200 `paired:false`)로 답하면 차는 앱이 앞으로 올 때 같은 정리를 한다.
- 차 네트워크가 끊기면(점검의 '차에서 서버에 닿는다' ✗) `adb -s emulator-5554 reboot`(약 15초, 시간대·앱 유지).

## 아직 없는 것

- 배터리 값 주입·충전 제안: PT 범위 밖(2단계 후보)이라 넣지 않았다.
- 녹화본: 위 진행을 리허설하며 화면 녹화로 뜬다(사람).
- 외부(HTTPS) 서버로 시연하려면 배포가 먼저다. 그때는 차 release 빌드 서버 주소와 점검 스크립트의 주소를 바꾼다.

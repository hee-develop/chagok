# 폰 캘린더 연결 (MVP 1)

정책서 10·11장 기준입니다. 폰이 기기 캘린더를 읽어 오늘·내일 일정을 서버로 보내고, 서버는 그 일정을 차량 응답(`/schedules/today`)의 출처로 씁니다.
서버가 캘린더 계정에 직접 붙지 않고 Android Calendar Provider(삼성·구글 캘린더가 동기화해 둔 것)만 폰이 읽습니다. 검증은 Android 기준입니다.

## 폰

- 출처 선택: `EXPO_PUBLIC_CALENDAR_SOURCE=mock|device`. **기본은 device**이고, `mock`을 명시했을 때만 목 캘린더(`fixtures/calendars/mock-device.json`)를 씁니다. 목 출처에서는 서버로 일정을 보내지 않아 서버는 픽스처를 그대로 씁니다(`scripts/e2e-phone.sh`는 mock을 명시합니다).
- 구현: `phone/src/features/calendar-select/`의 `CalendarSource`(`list`, `listEvents`) 뒤에 목(`calendarSource.ts`)과 실제(`deviceCalendarSource.ts`)가 있습니다. 실제 구현은 `expo-calendar/legacy` 함수 API를 씁니다(새 객체 API는 Expo Go에서 동작하지 않습니다).
- 권한: 캘린더 고르기 화면이 열릴 때 요청합니다(`READ_CALENDAR`·`WRITE_CALENDAR`는 라이브러리가 한 묶음으로 요청하며 앱은 읽기만 합니다). **거부하면** 목 캘린더로 넘어가지 않고 '캘린더 접근을 허용해 주세요. 허용해야 일정을 차에 보낼 수 있어요.' 안내와 [설정 열기]·[다시 시도]만 보입니다. 주 버튼은 비활성이고 '나중에 할게요'는 그대로 쓸 수 있습니다. 설정에서 허용하고 앱으로 돌아오면(AppState `active`) 자동으로 다시 읽습니다. 기기 캘린더가 0개면 '연결할 캘린더가 없어요…' 안내를 보입니다. 일정을 보낼 때는 권한 창을 띄우지 않고, 권한이 없으면 그냥 건너뜁니다.
- 기본 체크(10.2 종류 가르기): 캘린더 목록의 기본 체크는 Android 접근 수준으로 정합니다. 소유·편집 가능(`owner`·`root`·`editor`·`contributor`)이면 내 것·공유 캘린더라 체크하고, 읽기 전용(`read`·`respond`·`freebusy`·`none` — 공휴일·생일·구독)은 `isPrimary`여도 해제합니다. 접근 수준을 모르는 캘린더만 `isPrimary`를 따릅니다(`deviceCalendarSource.ts`의 `isDefaultSelected`).
- 읽는 범위: 고른 캘린더의 오늘·내일(Asia/Seoul 오늘 0시 ~ 모레 0시). 반복 일정은 해당 날짜의 인스턴스로 오며 id는 `<일정 id>@<시작 시각 ms>`입니다. 종일 일정은 UTC 자정으로 오는 날짜를 서울 날짜로 읽어 서울 자정 ~ 다음 날 자정(미포함)으로 보냅니다. 장소 칸은 `locationText`, 메모는 `notes`, 참석자는 이름만 보냅니다. 서버 상한을 넘는 글은 보내기 전에 자르고 일정은 200개까지 읽습니다. 참석자는 앞쪽 50개 일정까지만 10건씩 병렬로 읽고, 본인·주최자·이메일 형식 이름은 뺍니다. 보내기 직전에 직렬화 크기가 900KB(서버 상한 1MB의 여유분)를 넘으면 앞쪽 일정만 보냅니다. 캘린더 읽기·선택 조회·전송은 각각 10초 제한입니다.
- 보내는 때: (1) 앱을 열 때, (2) 앱이 앞으로 올 때(AppState `active`), (3) 캘린더 선택을 서버에 저장한 직후, (4) 앱이 앞에 있는 동안 3분마다(`REREAD_INTERVAL_MS`, `useEventSync`) 다시 읽어 바뀐 내용이 있을 때. (4)는 정책서의 '캘린더가 바뀔 때(앱이 깨어 있을 때)'를 변경 감지 대신 주기적 재읽기로 대신한 것이고, 뒤로 가면 멈추며 앞으로 오면 곧바로 한 번 읽고 다시 잇습니다. 거르기·읽기는 폰 안에서 끝나고 내용이 같으면 보내지 않습니다(같은 내용도 15분이 지나면 한 번 다시 보냅니다. 아래 '보내는 규칙'). 고른 캘린더는 서버에 저장된 선택을 읽어 정합니다. 선택이 없거나(`나중에 할게요`) 목 캘린더 id 선택(`source: "mock"`)이면 보내지 않습니다(목 id로 기기 일정을 조회해 빈 목록을 보내면 서버가 폰 출처로 굳기 때문). 서버가 재시작으로 선택을 잃으면, 앱이 떠 있는 동안 기억해 둔 마지막 선택을 다시 저장한 뒤 **일정도 반드시 다시 보냅니다**(같은 내용 생략을 건너뜀. 서버는 선택과 일정을 함께 메모리에 두므로 선택을 잃었다면 일정도 잃은 것입니다. 이 기억은 메모리에만 있어 앱을 껐다 켜면 사라집니다. 이동 일정 예외 이름만 폰 저장소(AsyncStorage)에 둡니다). 화면은 저장된 선택 중 이 기기에 있는 캘린더가 하나도 없으면 기본 선택(소유·편집 가능한 캘린더, 위 '기본 체크')으로 시작합니다.
- 보내는 규칙: 동시에 하나만 보냅니다(보내는 중에 또 불리면 하나로 합쳐 끝난 뒤 다시 읽어 한 번 더). 요청은 10초 제한(`requestWithTimeout`)이고, 화면이 내려가면 취소하며 취소·밀린 응답은 '보냈음'으로 기록하지 않습니다. 같은 내용(거른 뒤의 일정)은 `RESEND_UNCHANGED_AFTER_MS` = 15분 안에 다시 보내지 않고, 지나면 한 번 다시 보냅니다. 서버가 재시작해 폰 일정을 잊었거나 날짜가 지나 지웠을 수 있어서이며, 3분 주기(`REREAD_INTERVAL_MS`)의 5배라 3·6·9·12분 읽기는 건너뛰고 15분 읽기에 다시 보냅니다(읽는 시각이 조금 어긋나면 18분). 간격은 보내기를 시작한 때부터 잽니다. **생략하기 직전에 서버가 일정을 받은 적이 있는지 `GET /events`의 `receivedAt`으로 확인**하고(`fetchEventsReceivedAt`), null이면(재시작·초기화) 생략하지 않고 보냅니다. 확인 요청이 실패하면(네트워크·403 등) 알 수 없으므로 역시 보냅니다. 처음 보내거나 내용이 바뀔 때는 묻지 않습니다. 선택을 다시 저장한 직후 보내기가 실패해도 다음 읽기에서 `receivedAt`이 null이라 다시 보냅니다. 실패해도 화면에 알리지 않고 다음 기회에 다시 보내지만, 결과는 `lastResult()`에 남고 개발 빌드에서는 `[calendar-sync] PUT /events 실패: HTTP 413`처럼 단계와 HTTP 상태만(일정 내용 없이) 콘솔에 경고합니다.
- 앞에 있는 동안 3분 주기는 마운트 시점에 앱 상태(`AppState.currentState`)가 active일 때만 시작합니다. 뒤에서 마운트되면 처음 한 번만 읽고 앞으로 올 때 주기를 시작합니다.
- 문서에 남은 일(이번에 하지 않음): 백그라운드 새로 고침, 캘린더 변경 알림 구독(지금은 주기적 재읽기), iOS.

### 폰에서 이동 일정 거르기 (정책서 10.3 표 1~3번)

폰이 일정을 읽은 뒤 서버로 보내기 전에 거릅니다(`phone/src/features/calendar-sync/travelFilter.ts`). 판정 함수는 서버의 `server/src/noTravel.ts` 한 곳이고, 폰은 워크스페이스 하위 경로 `@chagok/server/no-travel`(폰 `dependencies`의 `@chagok/server`, 소스 그대로, 다른 모듈을 가져오지 않는 순수 함수 — `server/test/no-travel.test.ts`가 파일에 import 문이 없음을 검사합니다)로 가져다 씁니다. 서버도 같은 함수로 안전망 판정을 합니다.

| 순서 | 규칙 | 폰이 하는 일 |
| --- | --- | --- |
| 1 | 종일 | 서버로 이름만 보냄(메모·참석자는 비움). 장소 칸은 '어디로 갈까요?' 후보용으로 남기되 **온라인·건물 안 표시면 비워** 보냄. 온라인·건물 안 표시가 있어도 종일이면 이 규칙 |
| 2 | 온라인 | **보내지 않음**. 폰 로컬 목록에만 남음 |
| 3 | 건물 안 | **보내지 않음**. 폰 로컬 목록에만 남음 |

걸러진 일정은 제목·시각·이유(`online`|`meetingRoom`)만 폰 메모리 목록(`filteredEvents.ts`)에 두며 3단계 화면이 흐리게 보입니다(`docs/fill-places.md`). 일정을 읽을 때마다 새로 채워지고, 고른 캘린더가 없거나(`no-selection`) 권한이 없거나 캘린더를 읽지 못하면 이전 목록을 비웁니다. 장소 칸이 빈 일정은 건물 안으로 거르지 않습니다.

- 예외 기억: 걸러진 줄을 누르면 확인("‘제목’ 일정을 이동 일정으로 바꿀까요? 같은 이름 일정을 앞으로 차에 보내요." [바꾸기]/[취소])이 나오고, [바꾸기]를 눌러야 그 일정 제목(앞뒤 공백 제거·연속 공백 하나·대소문자 무시)이 폰 저장소(AsyncStorage `chagok.travelExceptions.v1`, 이름만, 최대 500개)에 남습니다. 같은 이름 일정은 다음부터 거르지 않고 보내며, 보낼 때 `travelConfirmed: true`를 달아 서버의 안전망도 건너뛰게 합니다(안 달면 서버가 같은 규칙으로 다시 이동 없음으로 봄). 바꾸는 즉시 다시 읽어 보내고, **서버로 보내지 못하면**(네트워크·권한·선택 없음) **이 일로 바뀐 것만** 되돌립니다: 예외 저장은 이 이름만 지우고(원래 예외였거나 저장소를 읽지 못한 동안이면 저장돼 있던 이름은 건드리지 않음), 거른 목록은 이 일이 뺀 줄만 도로 넣습니다(그 사이 다른 줄을 바꾸거나 새로 읽힌 목록을 덮지 않음). 줄이 사라지지 않게 하고 "바꾸지 못했어요. 일정은 그대로예요…"로 알립니다. 바꾼 직후 10초(`UNDO_VISIBLE_MS`) 동안 '되돌리기'가 보이고, 누르면 예외를 지우고(`travelExceptions.remove`) 다시 읽어 서버 일정을 교체해 그 일정이 차에서 빠집니다(되돌리기가 서버에 닿지 못하면 안내하고, 다음 3분 주기 읽기가 다시 보냅니다). 목록 화면에서 예외를 관리하는 일과 서버 `/skips`(같은 이름 이동 없음 기억 서버 목록)와 잇는 일은 다음 묶음(J2b)이며, `travelExceptions.ts`의 `subscribe`가 이름이 바뀔 때마다 알려 주므로 거기서 서버에 올리면 됩니다.
- 예외 목록 읽기: 저장소 읽기에 5초(`LOAD_TIMEOUT_MS`) 시간 제한이 있고, 읽지 못하면(오류·시간 초과) 읽기 실패로 표시하고(`readFailed()`) 이 세션에서 더한 이름만으로 동기화를 이어 갑니다(동기화가 멈추지 않음). 실패한 동안에는 저장소의 기존 목록을 덮어쓰지 않고, 다음 읽기에서 다시 읽어 메모리 변경과 합친 뒤 한 번 저장합니다(그동안 지운 이름은 되살리지 않음). 내용이 망가진 저장값은 빈 목록으로 보고 다음 저장 때 덮어씁니다.
- 온라인 판정(정책서 12장: zoom.us, meet.google.com, teams.microsoft.com, webex.com, 온라인, 화상, 비대면 — 장소·메모에서 찾음): 장소 칸·메모의 회의 **링크**(스킴이 있거나 호스트 뒤에 경로가 붙은 `zoom.us/j/1` 형태. 이메일·`zoom.us.example.com` 같은 다른 주소는 제외)는 온라인입니다. **호스트 이름만 스쳐 언급된** 경우('zoom.us 녹화본 참고')는 장소 칸 자체에 적혀 있거나 장소 칸이 비었을 때만 온라인으로 보고, 장소 칸에 실제 장소가 있으면 거르지 않습니다. 장소 칸의 '온라인'·'온라인 회의'·'화상회의'·'비대면 회의'·'Zoom'·'Google Meet'·'Teams'·'웹엑스'·'팀즈' 등은 **낱말 경계**로 봅니다(앞뒤가 글자로 이어지면 다른 말: '온라인마케팅협회 강남사무소'·'zoomcafe 강남'은 온라인이 아님. '온라인으로'처럼 '으로·로·에서'가 붙은 것은 같은 말). 장소 칸 전체가 '화상'·'비대면'·'줌'·'zoom'·'Teams'·'Meet' 한 단어(또는 'Zoom / Teams'·'줌 또는 Teams'처럼 이 말들만 이어진 것)일 때만 온라인입니다('화상 병원'·'줌 스튜디오'·'zoom 카페'·'Zoom Cafe 강남'은 아님). 'zoom'·'줌'·'teams'·'meet' 뒤에 회의를 뜻하는 말이 붙으면('zoom미팅'·'줌 회의'·'Teams Meeting'·'구글밋'·'웨비나') 어디에 있어도 온라인입니다. '온라인/오프라인'만 있으면 온라인이고, '온라인 또는 강남역'·'강남역 / 온라인'처럼 '또는·혹은·or·/'로 다른 장소가 이어지고 그 밖에 고유한 장소 이름이 남으면 실제 장소가 함께 있어 거르지 않습니다('7층 회의실 또는 온라인'은 둘 다 이동이 없어 거름). 제목만 보는 규칙('화상회의'·'온라인 회의'·'비대면 회의'·'Zoom 미팅'·'Teams 회의'·'줌 회의'·'웨비나' 등)은 **장소 칸이 비었을 때만** 씁니다('온라인 회의 준비' 일정이 스타벅스에서 열리면 거르지 않음). 회의 정보(캘린더 conference 데이터)는 Android 캘린더 API로 받지 못해 보지 않습니다.
- 건물 안 판정(12장 "실내 표시**만** 있다"): 장소 칸에서 실내 표시를 걷어내고 **'일반 말'만 남을 때**만 거릅니다. 강한/약한 표시 구분 없이 한 규칙입니다.

## 서버 API

데이터는 운전자 자리별로 따로 쌓입니다(폰 토큰이 있으면 그 자리, 토큰 없이 기기 id만 있으면 그 폰의 연결 전 버킷, 식별이 없으면 '기본 자리'. 차는 `driver=<seatId>`로 그 자리의 것을 읽습니다. 규칙은 `docs/pairing.md`). 인스턴스별 메모리 저장이며 재시작하면 초기화됩니다.

### `PUT /events` (폰 → 서버, 오늘·내일 일정 전체 교체)

```json
{
  "events": [
    {
      "id": "42@1794373200000",
      "calendarId": "3",
      "title": "팀 회의",
      "start": "2026-11-11T05:00:00.000Z",
      "end": "2026-11-11T06:00:00.000Z",
      "allDay": false,
      "locationText": "광주 육전집",
      "notes": "자료 챙기기",
      "attendees": ["김철수", "이영희"]
    }
  ]
}
```

응답 200: `{ "receivedAt": "2026-11-11T01:00:00.000Z", "stored": 1, "dropped": 0 }`. `dropped`는 오늘·내일(서울)과 겹치지 않아 거른 일정 수입니다.

- `travelConfirmed`(선택, boolean): 폰에서 "이동 일정이에요"로 바꾼 같은 이름 일정이면 `true`. 서버의 이동 없음 안전망을 건너뜁니다. 없으면 `false`로 보고 `GET /events`도 `true`일 때만 내려줍니다.
- 검증(400): 본문이 객체이고 `events`가 배열, 개수 200 이하, `id`·`calendarId` 1~100자, id 중복 없음, `title` 200자·`locationText` 300자·`notes` 2000자 이하(null 허용은 `locationText`·`notes`만), `attendees` 이름 문자열 50개 이하·각 100자 이하, `allDay` boolean, `start`·`end`는 오프셋 있는 ISO8601이고 달력에 있는 시각, `end >= start`. 본문 1MB 초과는 413. 상한은 `server/src/limits.ts`.
- 저장은 전체 교체입니다. 일정이 0건이어도 받은 것으로 칩니다.

### `GET /events?date=YYYY-MM-DD` (확인·차량용)

`{ "date": "2026-11-11", "receivedAt": "…" | null, "events": [ … PUT과 같은 모양 … ] }`. `date`를 생략하면 오늘(서울). 그날(서울)과 겹치는 일정만 시작순으로 줍니다. 잘못된 날짜는 400. 선택 캘린더 필터·장소 보정은 적용하지 않은 저장값 그대로입니다(차량은 `/schedules/today`를 씁니다).

### `DELETE /events` (개발·데모 전용 초기화)

저장된 폰 일정을 지워 `receivedAt`을 null로 되돌리고, `/schedules/today`·`/places`를 픽스처 출처로 복귀시킵니다. 같은 기기(127.0.0.1·::1)에서 온 요청만 받고 그 밖은 403입니다. 예: `curl -X DELETE http://127.0.0.1:8787/events`. 일정이 바뀌거나 비워질 때 사라진 일정 id의 3단계 보정도 함께 버립니다.

### 날짜 삭제

읽을 때와 `PUT`으로 교체할 때마다(타이머는 없음) 서울 오늘 0시 전에 끝난 일정은 지웁니다(종일 일정의 끝은 미포함이라 어제 종일 일정은 오늘 지워짐). 받은 시각(`receivedAt`)은 다음 PUT까지 남아 '폰이 보낸 적 있음' 표시로 쓰입니다.

## `/schedules/today`·`/schedules/places`의 출처

| 상태 | 출처 |
| --- | --- |
| 폰이 `PUT /events`를 한 번도 하지 않음 | 픽스처(`fixtures/schedules/gwangju-day.json`) — `at` 기준 상대 시각, 기존과 완전히 같음. 데모·차량 E2E가 이 경로 |
| 폰이 한 번이라도 보냄 | 폰 일정(0건이어도 빈 목록. 실제 사용자에게 목 일정이 보이면 안 되므로 픽스처로 돌아가지 않음) |

### 선택의 출처 규칙

서버는 선택에 `source`(`mock`|`device`)를 함께 저장하고 `GET /calendars/selection`이 돌려줍니다(`PUT`에 없으면 `mock`). `device`일 때만 목 캘린더 id 검사를 건너뜁니다. 선택은 **일정 출처와 같은 출처일 때만** 적용합니다.

| 일정 출처 | 선택 | 결과 |
| --- | --- | --- |
| 폰 일정 | `device` | 그 기기 캘린더 id의 일정만 |
| 폰 일정 | `mock` 또는 없음 | 거르지 않고 폰이 보낸 전부(목 id로 기기 일정을 지우지 않음) |
| 픽스처 | `mock` | 그 목 캘린더만 |
| 픽스처 | `device` 또는 없음 | 목 캘린더의 기본 선택(빈 목록이 아님) |

### 폰 일정일 때의 나머지 규칙

- 날짜: `at`(없으면 서버 시계)의 서울 날짜에 시작한 일정, 또는 전날 시작해 `at`에 아직 안 끝난 일정(`/schedules/today`). `/schedules/places`는 날짜로 거르지 않고 종일을 뺀 일정을 시작순으로 줍니다.
- 이동 없는 일정(`server/src/noTravel.ts`, 서버 안전망): 폰이 거르지 못한 일정(옛 앱, 픽스처·데모 경로)을 서버가 같은 판정으로 저절로 '이동 없음'으로 봅니다. 폰이 보낸 일정에 `travelConfirmed: true`가 있으면 건너뜁니다. 종일 일정은 거르지 않습니다. 차량 응답에서는 빠지고, `/schedules/places`에는 `noTravel: true`와 `noTravelReason`(`online`|`meetingRoom`)으로 남아 3단계가 흐리게 보이며 이유를 붙입니다.
  - 온라인 회의: 위 '온라인 판정' 규칙(회의 링크, 장소 칸의 낱말 경계 표시, 장소 칸 전체가 한 단어, 장소 칸이 빌 때의 제목·메모 호스트 이름).
  - 건물 안(`noTravelReason`은 `meetingRoom`): 위 '건물 안 판정' 규칙(고유한 장소 이름이 같이 있으면 거르지 않음). 온라인 표시가 같이 있으면 온라인 회의로 봅니다.
  - 잘못 거르면 일정을 차에서 잃으므로 확실한 표시만 봅니다('화상'이 긴 장소 이름 안에 섞이면 '화상전문병원'과 헷갈려 보지 않음).
  - 3단계 보정이 이깁니다: 장소를 넣으면 다시 차로 가고, 직접 '이동 없음'을 고르면 이유 없이(`noTravelReason: null`) 이동 없음이며, 보정을 지우면(`placeId: null`) 저절로 거르는 상태로 돌아갑니다. 픽스처 일정에도 같은 규칙을 쓰지만 해당하는 일정이 없어 데모·차량 E2E는 그대로입니다.
- 장소(좌표) 매칭: ① 3단계 보정(`PUT /schedules/:id/place`)이 가장 먼저. ② 자리의 장소 기억(차가 `PUT /places/memory`로 저장, 애매하지 않은 것만 확정하고 애매한 기억은 `suggestion`으로만 — `docs/place-resolve.md`). ③ 목 장소(`fixtures/places`의 검색 대상·추천) 이름이 장소 칸과 **정규화(앞뒤 공백 제거·연속 공백 하나·대소문자 무시)해서 완전히 같을 때만** `place`(좌표)를 확정합니다. **③·④(목 장소 이름 일치·부분 일치·제목 시드)는 기본 자리와 `FIXTURE_SEATS=1`에서만 쓰고 실제 자리(연결된 자리·연결 전 버킷)에서는 쓰지 않습니다.** ④ 이름이 일부만 겹치는 경우('잠실 실내 체육관'→'체육관', '광주'→'광주 육전집')와 지난번 기억(제목, `fixtures/places/remembered.json`)은 좌표를 확정하지 않고 `/schedules/places`의 `suggestion`(3단계 '여기 맞아요', 픽스처 일정과 같은 계약 — `docs/fill-places.md`)으로만 내립니다. 완전 일치가 있으면 후보는 내지 않습니다. ⑤ 아무것도 없으면 `place: null`. `locationText`는 보정하지 않은 한 캘린더의 장소 칸 그대로이고, 이동 없음은 차량 응답에서 뺍니다.
- 보정 키의 한계: 보정은 일정 id(`<기기 일정 id>@<시작 시각 ms>`)에 붙습니다. 일정 시간을 옮기면 id가 바뀌어 보정이 사라지고(새 일정으로 취급), 반복 일정은 날짜별 인스턴스마다 따로 보정해야 합니다. 폰이 일정을 교체할 때 더는 없는 id의 보정은 서버가 버립니다. 보정은 서버 메모리에만 있어 재시작하면 사라집니다.
- 서버 시계는 `createApp({ now })`로 바꿀 수 있어 테스트가 고정된 시각을 씁니다.

## 개발 서버를 같이 쓸 때 (주의)

- **폰 앱을 데모·차량 E2E용 서버(8787)에 붙이면** 폰이 한 번이라도 `PUT /events`를 하는 순간 그 서버의 `/schedules/today`가 폰 일정으로 바뀌어 데모·`pnpm e2e:car`의 픽스처 일정이 사라집니다. 서버 상태는 `GET /events`의 `receivedAt`으로 알 수 있습니다(null이면 픽스처, 값이 있으면 폰 일정). 되돌리려면 `curl -X DELETE http://127.0.0.1:8787/events`(또는 서버 재시작). 데모·차량 E2E 전에 `receivedAt`이 null인지 확인해 주세요.
- **`HOST=0.0.0.0`으로 열면** 같은 네트워크의 누구나 인증 없이 `PUT/GET /events`로 일정(제목·장소·메모·참석자)을 읽고 바꿀 수 있습니다. 그럴 때는 `EVENTS_LOOPBACK_ONLY=1`을 함께 줘서 같은 기기 요청만 받게 하세요(그 밖의 요청은 403, `adb reverse`로 붙는 폰 에뮬레이터는 호스트 127.0.0.1로 들어와 통과합니다). `DELETE /events`는 이 옵션과 무관하게 항상 같은 기기만 받습니다.

## E2E

`E2E_FLOWS=device-calendar pnpm e2e:phone` (에뮬레이터·Maestro 필요, 기본 flow 목록에는 없음). `scripts/seed-phone-calendar.sh`가 폰 에뮬레이터에 로컬 캘린더 `ChagokE2E`와 일정 3개(오늘·내일·3일 뒤)를 `adb -s <시리얼> shell content insert`로 심고, Metro를 device 출처로 띄워 `e2e/maestro/phone/device-calendar.yaml`을 돌린 뒤 심은 캘린더를 지웁니다. 실행 전에 Expo Go를 끄고 서버의 폰 일정을 `DELETE /events`로 비웁니다. flow는 우리 화면 제목이나 권한 창이 뜰 때까지 기다리다가 안 뜨면(다른 프로젝트·개발자 메뉴가 열린 경우) Expo Go를 끄고 우리 주소를 다시 여는 것을 최대 4번 합니다. 권한 창(Expo Go의 `ALLOW`, 시스템의 `Allow`·`허용`)을 허용하고, '캘린더 N개 연결하기'(N은 1 이상)를 누르면 `assert-device-calendar.js`가 선택의 source가 device인지, `GET /events`와 `/schedules/today`·`/schedules/places`를 확인합니다. 시드 스크립트는 `emulator-5554`를 거부합니다.
